# Stage 7 Query

Goals of this step:

- A flattened view of the tracked events in the warehouse, generated from the tracking plan.
- Three questions answered from that view.
- One insight, written into the progress file.

Model. `create_autogenerated_data_model` with `trackingPlanId`, `destinationId` from `list_destinations`, `modelType: view`, `eventSpecificationContextFiltering: true` when the tracking was implemented with Snowtype and `false` with direct tracker calls or CLI events, and `atomicFields` for the columns the questions need, such as `domain_sessionid` and `page_url`. It flattens every entity of the plan into columns and filters to the plan's event specifications, and stores the SQL without deploying it. Read it with `get_autogenerated_data_model`, run it through the warehouse MCP when one is connected, otherwise hand it over. Small touches are fine, like the table name or quoting, a rewrite is not: the generated SQL is the point. `get_semantic_model` then gives a semantic layer file for BI and AI tools. Redshift has no autogenerated model, and it keeps each self-describing event and each entity in its own table, joined back to `events`: write the queries by hand there, the querying docs below show the joins.

Questions, all against the view:

1. Events per event specification in the last day.
2. The latest events with their entity columns, to show the data is flat and typed.
3. Sessions per day, and how many of them reached the main action.

Insight. One sentence from the third question, for example the share of sessions in the last week that reached the action, followed by the one thing worth tracking next. Write both into the progress file.

Done when the view exists, the three questions returned rows, and the insight is recorded.
